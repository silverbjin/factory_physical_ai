# Phase 0 Risk Register

> Reviewed: 2026-08-28. Risk scores are planning estimates, not measured outcomes.

| ID | Risk | Evidence / current state | Likelihood | Impact | Mitigation and owner | Validation trigger / exit signal |
|---|---|---|---|---|---|---|
| R-01 | Teleoperation is unstable or unavailable | No manipulator, serial device, or camera was detected on the verified WSL host | High | High | Acquire/identify a LeRobot-supported leader/follower kit; perform no-motion port/camera checks, then documented calibration and short supervised recording | 10 repeatable short teleop episodes with no unclassified dropouts; device/safety manifest stored |
| R-02 | Local VLA training cannot run | GPU access is blocked by OS; VRAM and CUDA are unknown; torch/LeRobot absent | High | High | Restore WSL GPU access or use an approved remote CUDA host; start with a cost-capped SmolVLA installation/import and tiny smoke evaluation only | GPU/driver/VRAM + Torch CUDA + LeRobot import evidence; approved training budget |
| R-03 | LeRobot/SmolVLA setup has dependency or Python incompatibility | Official stack is documented, but no local install/import has occurred | Medium | High | Isolated project venv; pin resolved dependencies; record exact command and lockfile; retain ACT fallback only if SmolVLA gate fails | `lerobot` import and command help pass in isolated environment; no model download required |
| R-04 | Agent framework adds complexity without reliability | LangGraph is not installed; framework persistence is available but does not replace deterministic physical policy | Medium | High | Use a small deterministic state machine and provider adapter in MVP; spike LangGraph only behind the same contract | Restart/idempotency test passes without framework coupling; framework adoption requires a measurable advantage |
| R-05 | ROS–VLA coupling leaks unsafe control | ROS 2 Jazzy is present but no robot/simulator packages or hardware path are validated | Medium | High | Enforce VLA Skill and ROS execution contracts; keep raw ROS/motion out of Agent output; dry-run adapter first | Contract tests reject unbounded/raw motion fields; native robot PC dry-run produces typed results |
| R-06 | AMR/simulator work consumes schedule | Nav2/Gazebo packages are absent; visual fidelity offers little evidence value | High | Medium | Day-10 uses deterministic navigation mock; add headless Gazebo/Nav2 only for a defined integration criterion | MVP Agent recovery benchmark runs before any navigation installation effort |
| R-07 | Docker services cannot be reproduced | Docker daemon access denied for current user | Medium | Medium | Keep MVP native/local; request scoped daemon access before Compose work; document non-containerized hardware edge | `docker info` succeeds and a pre-existing or explicitly approved smoke image runs |
| R-08 | Camera observation quality/synchronization is insufficient | No camera enumeration; V1 requirements are not hardware-tested | Medium | High | Use one fixed 640x480@30 FPS camera initially, monotonic timestamps, and calibration manifest; add wrist camera only when evaluation proves need | Camera capture test records timestamp monotonicity and calibration version |
| R-09 | Soak/Chaos evidence starts too late | No runtime exists yet; 24 h target requires stable harness before week 6 | Medium | High | Add fault injection and run manifests with the Agent vertical slice; schedule soak only after deterministic regressions pass | At least representative Chaos cases run before starting a 24 h soak |
| R-10 | Secret/cost leakage from hosted AI or cloud GPU | No provider credential or GPU account has been validated | Medium | Medium | provider interface, environment-only credentials, token/cost fields, spend cap, redacted evidence | `.env` ignored; fake provider tests pass; real API use has explicit credentials and budget |

## Risk priorities

The critical path is R-02/R-03 (VLA readiness), R-01 (hardware/teleop), and R-04/R-09 (Agent reliability evidence). Navigation polish, additional cameras, and a full container topology are explicitly lower priority until the Day-10 vertical slice and VLA proof-of-life gates are complete.
