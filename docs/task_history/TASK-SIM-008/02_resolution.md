# Resolution — TASK-SIM-008

## Root Cause

The original bounded live run reached the Gazebo/ROS 2 startup gate but the
Codex sandbox denied DDS network-interface enumeration and UDP socket setup
(`getifaddrs: Operation not permitted` and `Error creating socket: Operation
not permitted`).  Consequently the ROS graph could not become ready and the
runner correctly emitted `SIM_NORMAL_E2E_BLOCKED`.

The current environment also exposed an independent import-isolation defect:
the Gazebo-only runner imported the separate MuJoCo backend eagerly, causing
`ModuleNotFoundError: No module named 'mujoco'` before runtime startup.

## Fix

- `src/simulation_runtime/__init__.py`: lazily expose Mission integration
  exports instead of loading them during every package import.
- `src/simulation_runtime/mission_integration.py`: load the MuJoCo backend
  only for the `mujoco` profile and return a fail-closed `MUJOCO_UNAVAILABLE`
  VLA failure when that optional component is absent.
- `tests/test_simulation_normal_system_e2e.py`: add an import-isolation
  regression test for the Gazebo system E2E module.

## Verification

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m pytest -q -p no:cacheprovider \
  tests/test_simulation_normal_system_e2e.py \
  tests/test_simulation_mission_integration.py
# 10 passed

PYTHONDONTWRITEBYTECODE=1 python3 scripts/run_simulation_normal_system_e2e.py
# run in the approved unrestricted runtime; exit 0
```

## Canonical Live E2E Result

`SIM_NORMAL_E2E_READY`; the live run completed source navigation, source
verification, `vla.execute`, destination navigation, final verification, and
mission completion.  `cleanup_complete` was `true`. This is the actual runner
terminal result, not acceptance proof for the limitation below.

## Evidence

`results/simulation/SIM-008_normal_system_e2e.json` was regenerated by the
successful canonical runner. It records Gazebo Harmonic as the integrated
world, `mujoco_live_world: false`, final verification `pass`, and the accepted
SIM-005/SIM-007 bindings.

## Remaining Limitations

The canonical ROS 2/Gazebo command requires a runtime that permits local DDS
interface discovery and UDP transport. It correctly remains blocked under the
restricted Codex sandbox; no fallback or synthetic success path was added.

The current runner launches the SIM-004 navigation proxy world while
`GazeboSystemWorld` keeps the SIM-008 Brake ECU transition and observations in
its in-process `state` dictionary. Therefore the generated `READY` evidence
does not prove the task-owned Gazebo world state or a Gazebo-side manipulation
transition, and cannot satisfy TASK-SIM-008 acceptance without a broader
runtime/world integration implementation.
